# 0.3.31 安装器修订 1

## 根因

用户从 0.3.30 覆盖升级时看到“XScreen 无法关闭”。检查时没有 XScreen 或 Setup 进程。当前用户安装登记仍为 0.3.30，目录为 `D:\Apps\XScreen`；已安装卸载器和本次 Setup 临时目录中的 `old-uninstaller.exe` 与 0.3.30 构建保存的卸载器完全一致，SHA256 为 `deab5beb0e7983e763793bc0a83075242d1276cb6596f1f7fd817b36a9e7421b`。

固定版本 electron-builder 26.15.3 的 `un.onInit` 在静默模式下先调用 `un.checkAppRunning`，然后才执行 `initMultiUser`。我们的 `customCheckAppRunning` 同时调用了要求 `$installMode == CurrentUser` 的目录校验，此时变量尚为空，因此返回错误 2。外层旧版本卸载循环把任何非零错误重试五次后都显示通用的“无法关闭”消息。

离线源码 VM 在 `$installMode` 为空、应用互斥体不存在、当前用户安装登记有效的条件下复现了该错误，文件操作为 0。基线证据为 `analysis/evidence/installer-upgrade-preinit-baseline.json`。原有测试始终从已初始化的 CurrentUser 状态开始，漏测了 stock 模板的真实调用顺序；本次已补齐。

## 修复

- 新卸载器在初始化前只检查互斥体；初始化后的 `customUnInit` 和最终检查仍完整校验当前用户、登记目录、系统目录与重解析点。运行中或访问被拒绝仍阻止操作。
- 仅修改新卸载器不能修复已经安装的旧卸载器。因此安装器为已知的 0.3.29–0.3.31 改用当前受检的产品文件清单进行升级清理，完全不调用旧卸载器。
- 旧版本的产品路径集合冻结在 `tests/Fixtures/installer-upgrade-reference.json`。打包时要求当前卸载清单覆盖它；未知旧版本在修改文件前停止。
- 同目录和换目录升级均先检查登记、目录与快捷方式，保留用户偏好、日志及其他非产品文件。删除失败立即停止并保留登记供重试；已删除文件不会自动回滚。
- 旧卸载器文件本身也改为检查删除结果，避免删除失败后继续安装。

应用载荷仍为 0.3.31，安装器文件版本为 **0.3.31.1**。静态构建仍使用 UninstallerReader 提取卸载器，禁止执行生成器或通过 Wine/VM 回退执行。

## 验证边界

安装器行为回归 **53 项全部通过**，覆盖旧静默启动顺序、互斥体、三个旧版本、同目录及换目录升级、未知版本、占用文件、占用卸载器、重试、目录、快捷方式和用户数据保留。安装包静态验证 **550 项全部通过**，523 个应用载荷文件的哈希保持一致。只运行源码 VM 与静态验证；未执行安装器、卸载器或正式应用，未修改实际安装登记或显示器设置。真实升级仍需用户手动验收。
